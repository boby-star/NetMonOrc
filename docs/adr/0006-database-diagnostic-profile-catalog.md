# ADR 0006: Каталог DiagnosticProfile у PostgreSQL

Статус: прийняте локальне рішення реалізації доручених resource CRUD та
reconciliation. Нові DSL kind, математичні правила чи HTTP маршрути не вводяться.

Зовнішній файл профілю не забезпечує узгодженості з REST-змінами Monitor
і не може бути джерелом істини після появи редагування через панель.
Тому Monitor і DiagnosticProfile зберігаються в одному resource registry.
Bootstrap імпортує початкові записи один раз; видалення зберігає marker.
Явний POST/apply може створити новий UID після видалення.

Кожна зміна перевіряє весь об’єднаний граф в одній транзакції під існуючим
resource advisory lock. Compilers залишаються чистими, профілі компілюються
раніше Monitor незалежно від порядку документів. Максимум 4096 ресурсів/8 MiB
обмежує витрати цієї стратегії для дослідницького deployment. Це свідомий
компроміс до потреби в інкрементальному dependency index.

Effective revision містить hash нормалізованої залежності, а resourceVersion
відображає власний маніфест. Зміна профілю не створює фіктивний PUT Monitor.
Apply фіксує залежні Monitor як implicit targets та чекає їхніх ACK; звичайний
PUT повертає збережений desired state без обіцянки завершеного rollout.

Використано наявне graceful runtime reconciliation одного активного Monitor.
Динамічний multi-Monitor runtime не додається разом із цим каталогом.
Видалення профілю з enabled references заборонене. Раніше допустиме disabled
посилання без профілю залишається валідним; activation без профілю відхиляється.
