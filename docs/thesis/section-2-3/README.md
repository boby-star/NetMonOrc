# Матеріали підрозділу 2.3

- `section-2-3.docx` — редагований підрозділ для перенесення до записки.
- `section-2-3.pdf` — контрольний вигляд документа.
- `section-2-3.md` — текст, формули LaTeX і посилання на рисунки.
- `assets/` — дві схеми у PNG та їх вихідні описи Graphviz.
- `build_document.py` — відтворення Word-документа з Markdown.

Параметри оформлення: A4, Times New Roman 14 pt, інтервал 1,15;
поля: ліве 3 см, праве 1,5 см, верхнє й нижнє 2 см.
Таблиці — 11 pt, псевдокод — 9,5 pt. Формули у Word редаговані
математичні об'єкти, а не зображення. PDF має 12 сторінок.
Після перенесення до основної роботи кількість сторінок залежатиме від її стилів.

Матеріал містить 2 прості формули (2.5–2.6), 5 таблиць (2.3–2.7),
2 рисунки (2.2–2.3), 2 алгоритми з псевдокодом (2.1–2.2).
Нумерацію обрано як продовження наданих підрозділів 2.1–2.2;
під час остаточного оформлення її потрібно звірити з усією запискою.
Позначки `<!-- PAGE -->` в Markdown відділяють змістові частини чернетки
та не створюють примусових розривів у Word.

Основа тексту: §1.4, §2.1–2.2 наданої записки;
§4.8–4.9 `NetMonOrc_TZ_v1alpha1.md`;
§11.3–11.6 `NetMonOrc_DSL_Schema_v1alpha1.md`;
раніше погоджені у розмові правила бюджетів, повторів, підтвердження,
вибору агента та діагностичних епізодів.
Приклади й схеми розроблено для цього підрозділу. Числа у прикладі
ілюструють обчислення, а не результати проведених експериментів.
Текст описує алгоритм і задум програмної реалізації, не підтверджує
наявність працюючого Controller/Agent. Початковий DOCX користувача не змінено.

Для перебудови потрібні Python з python-docx, Pandoc і Graphviz:

```bash
python build_document.py
```

PDF отримано конвертацією DOCX через LibreOffice. Для повторної конвертації:

```bash
soffice --headless --convert-to pdf --outdir . section-2-3.docx
```
