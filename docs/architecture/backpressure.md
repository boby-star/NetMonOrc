# Заповнення черги Agent

Spool зберігає не більше 1000 observations, до 8192 байтів кожна. Новий
probe спочатку резервує місце результату; regular і diagnostic lanes не
можуть одночасно зайняти останній слот. При заповненні regular scheduler
припиняє нові probes. Уже записані результати не витісняються заради нових.
Після durable ACK файл видаляється, каталог синхронізується, місце звільняється.

На рестарті Agent читає приватну чергу, перевіряє identity та формат, а потім
доставляє результати з початковими ID. Controller ACK надходить тільки після
COMMIT; повтори не створюють додаткових observations. Старі observations
залишаються історією й не повертають live Assessment до застарілого стану.
За тривалої відсутності свіжих результатів coverage зменшується, а TTL
дає unknown, а не автоматичну відмову сервісу.

Критична перевірка TestDiskSpoolBackpressureAndResume використовує справжній
приватний каталог і HTTP server. 1000 початкових записів створено як fixture,
це не вимірювання 1000 фізичних probes. При повній черзі сервер не отримує
запитів; після одного ACK отримує один запит, результат якого займає слот.
Після закриття/відкриття spool всі 1000 pending records збережені; batch ACK
дренує їх без втрат. Перевірка пройшла з race detector. Приклад команд:

```bash
go test -race ./internal/agent -run TestDiskSpoolBackpressureAndResume -count=1 -v
```

Повний Agent reconnect/PG replay перевіряє distributed_smoke.py окремо.
Цей тест не доводить поведінку при фізичному пошкодженні диска, ENOSPC,
раптовій втраті живлення або довільній тривалості мережевої відмови.
Помилки запису завершують Agent з помилкою; він не підтверджує незбережений
результат як доставлений. Автоматичного збільшення spool або прихованого
видалення найстаріших результатів у цьому мінімальному профілі немає.
