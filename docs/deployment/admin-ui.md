# Адмінка: навігація та принципи Нільсена

Панель має окремі розділи замість однієї довгої сторінки. Бокова навігація
групує моніторинг, дослідження, конфігурацію та адміністрування. Вибір Monitor
залишається зверху робочого простору; підказки каталогу допомагають вибрати ID.
У межах доступного каталогу початковий research-web замінюється на наявний Monitor,
якщо такого стандартного ID немає. Можна ввести ID поза першою сторінкою каталогу.

## Реалізовані принципи

| Евристика | Реалізація |
|---|---|
| Видимість стану | Час оцінки, loading/aria-busy, disabled під час запиту, окремі стани ресурсу та покриття |
| Відповідність предметній області | Українські назви розділів, зрозумілі health labels, пояснення різниці між доказами й доступністю |
| Контроль користувача | URL hash/back/forward, закриття мобільного меню Escape, відмова від небезпечної дії у confirm |
| Узгодженість | Єдиний локальний Manrope, палітра, форми, таблиці, focus outlines та статусні badges |
| Запобігання помилкам | Підтвердження DELETE/revoke/cancel/зміни прав; перевірка Monitor ID; незбережена чернетка перед switch/logout/unload |
| Впізнавання замість запам’ятовування | Постійне меню, активний розділ, breadcrumbs, список Monitor, підписи полів |
| Ефективність | Окремі робочі розділи, збереження стану відвіданих модулів, клавіатурна навігація та прямі hash links |
| Естетика та мінімалізм | Ієрархія заголовків, оглядові показники, нейтральний фон, один основний колір дій, технічні деталі у disclosure |
| Відновлення після помилок | Видимі помилки API/валідації, повтор оцінки, збереження останнього знімка з явним маркером застарілості |
| Допомога | Пояснення полів, обмежень пароля, семантики ACK, стану apply та походження доказів |

Це застосування евристик до інтерфейсу, а не звіт користувацького дослідження
чи сертифікація WCAG. Ніяких оцінок доступності або діагнозів браузер не вигадує.

## Поведінка

Оцінка поточного Monitor запитується кожні 5 секунд. Огляд усієї інфраструктури
має власний timestamp і кнопку оновлення: його показники не є live-графіком.
При помилці polling попередній знімок зберігається з маркером застарілості;
здоровий стан не підставляється замість відсутньої відповіді.

Модулі завантажуються при першому відкритті. Повернення до відвіданого модуля
зберігає фільтри, вибір і YAML/batch draft. Switch Monitor або вихід можуть
знищити чернетку — для цього є підтвердження; перезавантаження/закриття вкладки
захищається beforeunload. Чернетки не записуються у localStorage. Після успішного
apply пакет вважається переданим серверу; підтвердження виконання показує Operation.

У мобільному вигляді бокова панель прихована. Кнопка меню має aria-expanded,
Escape закриває панель і повертає фокус на кнопку. Таблиці прокручуються всередині
розділу. Є skip link і видимий keyboard focus. Стани позначаються текстом разом
із кольором. Недоступні за scopes розділи/мутації приховані, але вирішальними
залишаються серверні ACL. Viewer отримує read-only редактор.

Manrope з кирилицею постачається разом із застосунком у public/assets;
запитів до Google Fonts/CDN при використанні панелі немає. Ліцензія SIL OFL
зберігається поруч. Controller видає TTF лише зі static assets із MIME font/ttf;
довільні файли/ключі та traversal не відкриваються.

## Перевірка кнопок

Сценарій `scripts/lab_admin_ui.py` використовує PostgreSQL, Controller, двох
справжніх mTLS Agents і Chromium. Browser driver натискає видимі елементи через
pointer events, перевіряє API/DOM наслідки, dialogs, desktop/mobile та viewer.
Паролі надходять через stdin; тестові credentials для продовження невдалого
запуску лишаються тільки у приватному .local каталозі власного стенда.
Не запускайте цей сценарій на користувацькій/production БД.

```sh
python3 scripts/lab.py prepare --project YOUR_NEW_PROJECT --prefix 10.247
python3 scripts/lab.py up --project YOUR_NEW_PROJECT --prefix 10.247 --ui-port 18448
python3 scripts/lab_admin_ui.py --project YOUR_NEW_PROJECT --prefix 10.247 --output .local/YOUR_NEW_BROWSER_RESULT
python3 scripts/lab.py down --project YOUR_NEW_PROJECT --prefix 10.247
```

Оберіть вільні мережі й порт. Сценарій створює власні resources/users і змінює
пароль свого test admin; credentials не експортуються у публічні докази.
Зафіксовано окремо натиснуті контролі та початковий inventory disabled-кнопок.
Немає твердження, що пройдено всі можливі комбінації станів: пагінація потребує
достатніх даних, а fallback evidence — справжньої технічної помилки виконавця.
[Фактичні результати й знімки](../experiments/admin-ui-2026-11-25/README.md).

## Оновлення встановленого master

Після отримання коду з гілки prototype/minimal-research, з кореня checkout:

```sh
git pull --ff-only
sudo bash install.sh master --action update --build --source-dir "$PWD"
```

Для custom install-dir/image вкажіть їхні чинні значення. За корпоративного
build proxy додайте --build-ca з довіреним CA bundle. Дані БД зберігаються.
Оновлення не виконує SSH/deploy на віддалені сервери автоматично.
