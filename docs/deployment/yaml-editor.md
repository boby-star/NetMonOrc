# Редактор одного ресурсу: YAML та точне текстове подання

У розділі «Конфігурація моніторингу» можна вставити один manifest YAML або JSON,
перевірити його, переглянути план і створити чи замінити ресурс. Обидва редактори
тепер передають текст серверу без перетворення Spec через JavaScript numbers.
При відкритті збереженого ресурсу textarea використовує серверний `source`.

## Відкриття та збереження

GET одного ресурсу й успішні POST/PUT повертають чинний View із додатковим
полем `source`. Це нормалізований JSON manifest як рядок: впорядковані ключі,
незмінені числові значення/типи. `source`, manifest, UID, resourceVersion та
ETag належать одному прочитаному або записаному ресурсу. Другого запиту для
збирання тексту та версії немає. JSON-поле manifest залишається для сумісності.

Редактор використовує `source` після відкриття й після запису. Так `1.0` і
`9007199254740993` не проходять через JSON.parse/stringify браузера. Подання
не є архівом вихідного YAML: коментарі, anchors, стиль і порядок ключів не
відновлюються. Перевіряються значення, типи та effective revision, не тотожність
вихідних байтів файла.

Валідація й preview використовують спільні config endpoints. Перед записом
серверний prepare повертає `documents[]` з kind/name/source кожного manifest;
браузер бере звідти ідентичність, але надсилає вихідний текст. Заміна забороняє
зміну kind/name і використовує ETag саме завантаженого ресурсу. Prepare не
оновлює цей If-Match свіжішою версією. Якщо ресурс змінили паралельно, PUT дає
412; локальна чернетка лишається, і можна завантажити актуальний ресурс.

POST залишається create-only: наявний ресурс не перезаписується. Збереження
незмінного spec може створити нову source version за чинними правилами CRUD,
але не повинно змінити effective hash або створити нове джерело доказів.

## Перенесення до пакета

Кнопка «Підготувати пакет із відкритого маніфесту» підтримує YAML і JSON.
Server documents дозволяють скласти ConfigBatch без браузерного округлення.
Для того самого завантаженого kind/name береться його resourceVersion; для
іншої ідентичності задається null (create-only). Це зберігає захист старої
чернетки від тихого перезапису новіших даних. Для кількох документів використайте
[пакетний редактор](yaml-web.md) безпосередньо.

## REST та обмеження

Одиночні `/api/v1/resources/{kind}` POST та `/{name}` PUT приймають JSON як
раніше, а також application/yaml, application/x-yaml, text/yaml. YAML проходить
спільний bounded decoder. У CRUD дозволено один manifest без requestId та
expectedVersions; batch conditions не ігноруються. Для пакетів використовується
config/apply. URI, manifest identity та If-Match перевіряються сервером.

Права, CSRF, same-origin та admission не змінено. `source` доступне разом із
відповідним View; prepare documents мають ті самі права, що config/prepare.
Текст документа обмежено 1 MiB. Якщо форматування з відступами не вміщується,
повертається компактний JSON. HTML-текст усередині рядків не роздувається
непотрібним екрануванням при формуванні документа; зовнішній JSON response та
React textarea зберігають звичайне екранування для показу даних.

[Натурне приймання](../experiments/yaml-editor-2026-11-22/README.md) підтверджує
YAML save/reload, точні числа в UI/БД, незмінний effective hash, копіювання в
пакет і 412 при старому If-Match. Це продовження редактора в межах наявних
kind DSL, без розширення мережевих перевірок або алгоритму Assessment.
